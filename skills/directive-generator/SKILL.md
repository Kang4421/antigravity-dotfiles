# Directive Generator (실행 지시문 생성 엔진)

모델에게 감정이나 페르소나를 부여하는 일반 프롬프트와 달리, 기계적이고 엄격한 실행을 담보하는 **순수 명령형 지시문(Action Directive)**을 생성합니다.

---

## 🔒 핵심 지시문 철학 (Core Principles)

1. **No-Persona, No-Heading**: "너는 ~ 전문가다", 친절한 인사말, `## Core` 같은 마크다운 헤딩을 일체 배제합니다.
2. **Action-Oriented (명령조 종결)**: 모든 문장은 `~하라`, `~해라`, `~할 것`의 단호한 명령조로 작성합니다.
3. **High Density (고밀도 제약)**: 전체 길이는 한눈에 파악 가능한 200~600자 내외로 압축하며, 불필요한 미사여구를 제거합니다.

---

## ❓ Socratic Clarification Gate (소크라테스식 1문 1답)

사용자의 입력이 극히 모호하거나 핵심 조건이 결핍되어 있어 지시문 합성 시 심각한 왜곡 위험이 있을 때 발동합니다:

1. **1턴 1질문 원칙 (Never Batch Questions)**: 절대로 여러 개의 질문을 쏟아내지 않고, 가장 크리티컬한 **단 하나의 질문**만 던집니다.
2. **A안 권장 배치 (Yes-Agreement)**: 사용자가 "A" 또는 "네"라고만 답해도 즉시 최적의 의사결정이 진행되도록 가장 표준적인 해결책을 `A. [권장]`에 배치합니다.
3. **사용자 위임 즉시 채택 (Delegation Rule)**: 사용자가 "알아서 해줘", "상관없어", "네가 골라줘"라고 답하면 되묻지 않고 A안을 즉시 확정 채택하여 지시문을 완성합니다.
4. **경미한 모호성은 즉시 생성**: 사소한 디테일로 불필요한 질문을 남발하지 않고, 의도가 명확한 경우 곧바로 지시문 출력을 진행합니다.

---

## 📐 TACO 생성 프레임워크

모든 지시문은 아래 4대 불변 요소를 반드시 포함하여 합성합니다:

- **T (Target Scope)**: 처리할 대상 데이터 또는 입력의 범위를 명확히 규정 (예: "제공된 회의록 원문에서...")
- **A (Action Verb)**: 구체적이고 검증 가능한 실행 동사 (예: "...핵심 결정 사항 3가지를 추출하라.")
- **C (Strict Constraint)**: 환각 및 탈선을 막는 엄격한 금지 조건 (예: "원문에 없는 내용은 일절 추론하지 마라.")
- **O (Output Shape)**: 반환될 산출물의 정확한 포맷 (예: "불릿 기호(-)와 한 줄 요약 형태로 반환하라.")

---

## ⚡ 2단 적응형 안전장치 (2-Tier Adaptive Architecture)

작업의 복잡도에 따라 형식을 2가지로 자동 분기합니다:

### 1. 단순 유틸리티 (Simple Task: 요약, 파싱, 포맷 변환 등)
- **포맷**: 1~2문단의 단단한 자연어 텍스트 블록
- **특징**: 목록 기호 없이 문장 간 인과관계를 쉼표와 마침표로 엮어 원클릭 실행에 집중

### 2. 복잡 추론형 (Complex Task: 다단계 판단, 코드 리팩토링, 논리 검토 등)
- **포맷**: 명령형 실행 스텝(`1.`, `2.`, `3.`) + 자가 검증 제약
- **특징**: 추론 탈선을 막기 위해 **단계별 순차 실행 강제** 및 **자가 검증 게이트(Verification Condition)**를 지시문 말미에 주입

---

## 📋 출력 가이드라인 (Output Guidelines)

사용자에게 결과를 반환할 때는 다음 규칙을 엄격히 준수합니다:

1. **상단 사설 완전 생략**: "지시문을 만들어 드렸습니다" 등의 인사말 없이 즉시 코드 블록으로 시작합니다.
2. **독립 코드 블록 제공**: 언어 태그 `text`의 마크다운 코드 블록 안에 지시문 본문만 담습니다.
3. **동적 슬롯 가이드**: 코드 블록 하단에 사용자가 실제로 채워 넣을 가변 영역(예: `[분석할_URL]`) 안내를 1~2줄로 콤팩트하게 부착합니다.

## 💡 Few-Shot Examples

### 예시 1: 모호한 입력 접수 시 (소크라테스식 1문 1답 발동)
- **사용자 입력**: "이거 보고서 좀 요약해줘."
- **스킬 응답**:
  > 대상 문서의 포맷과 핵심 요약 목적이 명시되지 않았습니다.
  > 
  > **질문**: 어떤 관점을 중심으로 요약 지시문을 작성할까요?
  > - **A. [권장]** 의사결정권자(경영진) 보고용: 핵심 결론 및 액션 아이템 중심 3줄 요약
  > - **B.** 실무진 분석용: 원문의 데이터 수치와 세부 근거를 빠짐없이 포함한 분석 요약
  > - **C.** - (직접 입력)

### 예시 2: 단순 작업 확정본 (유튜브 대본 핵심 요약 지시문)
```text
제공된 대본 텍스트를 분석하여 핵심 주장 3가지와 근거 수치를 추출하라. 원문에 없는 맥락을 자의적으로 해석하거나 외부 상식을 덧붙이지 마라. 불필요한 서론과 결론 인사말을 일절 배제하고, '핵심 주장 - 근거 수치'의 한 줄 불릿 목록 3개만 간결하게 출력하라.
```
* **가변 슬롯**: 대본 텍스트를 본문 끝에 바로 붙여넣어 실행하십시오.

### 예시 3: 복잡 작업 확정본 (데이터 파싱 및 결측치 보정 지시문)
```text
제공된 CSV 원시 데이터를 다음 절차에 따라 정제하라:
1. 'user_id'가 중복된 행을 식별하여 가장 최신 타임스탬프를 가진 1개 행만 남기고 제거하라.
2. 'age' 필드가 공란이거나 음수인 경우 전체 유저의 중앙값으로 대체하고, 'status' 필드가 누락된 경우 기본값 'inactive'를 부여하라.
3. 정제 전후의 총 행 수 변화와 보정된 결측치 개수를 요약한 JSON 객체 형태로 최종 출력하라.
단, 원본 데이터의 날짜 포맷(YYYY-MM-DD)을 임의로 변경하지 말고, 의심스러운 이상치는 삭제하지 말고 별도 'anomaly' 플래그를 달아 보존하라.
```
* **가변 슬롯**: `[CSV_DATA]` 영역에 원시 데이터를 주입하십시오.
