<Purpose>
사용자가 특정 도메인, 제품군, 기술 스택, 아이디어, 체크리스트 등에 대해 리스트업을 요청할 때,
감질나는 소량 출력이나 불필요한 중간 되물음을 완전히 배제하고,
누락 없이 20~30개 이상의 전수 항목을 3~5개의 MECE 카테고리로 분류하여
마크다운 표(Table) 기반의 고밀도 메타데이터로 단 1턴에 일목요연하게 완결 제공합니다.
</Purpose>

<Use_When>
- 사용자가 "리스트업해줘", "목록 뽑아줘", "후보군 정리해줘", "전부 나열해줘"라고 요청할 때
- 특정 분야의 대안, 솔루션, 툴, 제품, 아이디어를 폭넓고 체계적으로 한 번에 조망하고 싶을 때
- 단순 텍스트 나열이 아니라 속성별 비교가 가능한 정돈된 표(Table)로 대량 데이터를 정리하고 싶을 때
- `/list-up` 명령어가 호출되었을 때
</Use_When>

<Do_Not_Use_When>
- 1~3개의 최적 추천안만 좁혀서 심층 분석하는 단일 의사결정 요청인 경우
- 사용자가 "간단히 3개만 말해줘"처럼 소량의 축약 답변을 명시적으로 요구한 경우
- 리스트업이 아닌 순수 코드 디버깅, 단일 스크립트 작성, 단순 팩트 단답형 질문인 경우
</Do_Not_Use_When>

<Core_Principles>

### 1. 원샷 전수 일괄 출력 원칙 (Full Dump Guarantee)
- **중도 질문/페이징 절대 금지**: "5개만 보여드리고 원하시면 더 말씀해주세요", "더 볼까요?" 식의 되물음을 원천 배제합니다.
- **최소 수량 보장**: 사용자가 수량을 명시하지 않아도 **최소 20개~30개 이상**의 항목을 1회 응답에 전수 출력합니다. 사용자가 `--count 50`처럼 지정한 경우 해당 수량을 누락 없이 채웁니다.

### 2. MECE 2단계 구조화 (Categorized 2-Tier Layout)
- 30개의 항목을 단일 표나 줄글로 길게 쏟아내지 않습니다.
- 상호 배타적이고 전체를 포괄하는(MECE) **3~5개의 상위 카테고리(분류 축)**를 먼저 수립하고, 각 카테고리별로 분할된 표를 렌더링하여 인지 과부하를 막고 구조적 탐색을 가능하게 합니다.

### 3. 고밀도 표준 메타데이터 스키마 (Unified Metadata Schema)
- 모든 카테고리의 표는 일관된 메타데이터 컬럼을 갖추어 비교 편의성을 극대화합니다.
- **기본 표준 표 서식**:
  ```markdown
  | 순번 | 항목명 (이름/도구/아이디어) | 핵심 설명 (1~2줄 본질) | 최적 활용 상황 / 핵심 강점 | 태그 / 분류 |
  | :---: | :--- | :--- | :--- | :--- |
  ```
- 도메인 특성(예: 비용/라이선스가 중요한 소프트웨어 툴, 출시일/가격이 중요한 전자기기 등)에 따라 컬럼 1~2개를 맞춤형(예: 비용, 난이도, 지원 플랫폼 등)으로 유연하게 조정할 수 있으나, 가독성과 비교 가능성을 반드시 유지합니다.

### 4. 지능형 적응 소싱 (Adaptive Sourcing)
- **창의·기획·아이디어·브레인스토밍**: AI의 다각도 프레임워크(타깃별, 구현 난이도별, 비즈니스 모델별 등)를 통해 내부 지식으로 고속 발산.
- **실존 제품·최신 도구·시장 기업·기술 스택·장소 등 팩트 영역**: `search_web` 도구를 지능적으로 활용하여 최신 실존 데이터를 수집하고, 실존 여부와 정확도를 교차 검증한 후 리스트업합니다.

### 5. 토큰 세이프가드 및 제로 채터 (Density Safeguard & Zero-Chatter)
- 수십 개 항목의 표가 LLM 출력 토큰 한계로 중간에 끊기거나(Truncation) 잘리지 않도록 장황한 인사말, 사설, 중복 서론을 생략합니다.
- 정보 가치가 없는 수식어를 배제하고, 명사구 및 핵심 요약 위주의 초고밀도 문장으로 표를 작성합니다.

</Core_Principles>

## 🔄 실행 워크플로 (Execution Workflow)

### Step 1: 요청 분석 및 스코프 확정
- 사용자 입력에서 주제, 타깃 도메인, 요구 수량(지정 없으면 기본 20~30개), 검색 필요 여부를 파악합니다.

### Step 2: 3~5개 MECE 분류 축 설계
- 주제를 다각도로 조망할 수 있는 분류 기준을 수립합니다.
  - *예시 (개발 도구)*: 1. 경량/오픈소스 진영, 2. 엔터프라이즈/올인원 플랫폼, 3. 신흥 AI 기반 차세대 도구, 4. 셀프호스팅/온프레미스 특화
  - *예시 (비즈니스 아이디어)*: 1. B2B SaaS 자동화, 2. 긱이코노미/플랫폼, 3. 하이퍼로컬 커뮤니티, 4. 프리미엄 구독 서비스

### Step 3: 소싱 및 검증
- 팩트/실존 데이터가 필요할 경우 즉시 `search_web`으로 최신 후보군과 특성을 조회합니다.
- 중복 항목을 제거하고 각 카테고리별로 5~8개씩 균형 있게 배치합니다.

### Step 4: 원샷 전수 렌더링
- 상단에 리스트 개요(총 N개 항목, M개 카테고리)를 1~2줄로 요약한 직후, 곧바로 카테고리별 표를 연속 렌더링합니다.

### Step 5: 후속 액션 연계 가이드
- 출력 말미에 사용자가 다음 작업을 쉽게 이어갈 수 있도록 1~2줄의 콤팩트한 가이드를 덧붙입니다:
  > *"특정 항목의 상세 비교, 파일(MD/CSV) 저장, 또는 선택 항목에 대한 심층 구현/분석이 필요하시면 번호를 말씀해 주세요."*
