# 프롬프트 엔지니어링 프레임워크 및 변수 가이드 (Frameworks & Variables)

## 1. 프롬프트 구조화 프레임워크

### A. CRISPE 프레임워크
* **Capacity and Role (역할과 역량)**: AI가 수행할 최적의 페르소나 및 전문 도메인
* **Insight (맥락 및 배경)**: 왜 이 작업이 필요한지, 어떤 상황인지에 대한 정보
* **Statement (구체적 지침)**: 명확하게 수행해야 할 작업
* **Personality (말투 및 스타일)**: 전문적, 친절함, 간결함 등 톤앤매너
* **Experiment (시도 및 대안)**: 여러 대안 제시 또는 다각도 분석 유도

### B. CLEAR 프레임워크
* **Concise (간결성)**: 불필요한 사족 배제
* **Logical (논리성)**: 순차적 작업 단계
* **Explicit (명시성)**: 원하는 바를 정확하고 구체적인 단어로 지시
* **Adaptive (적응성)**: 예외 상황 대처 방법 제시
* **Reflective (반성/검증)**: 출력 전 검증 단계 포함

## 2. 동적 템플릿 변수 (`{{variable}}`) 처리 규칙

[linshenkx/prompt-optimizer](https://github.com/linshenkx/prompt-optimizer)의 핵심 강점 중 하나는 재사용 가능한 프롬프트 자산(Reusable Prompt Assets) 관리입니다.

### 변수 보존 원칙 (Variable Preservation Rules)
1. **변수 유지 필수**: 원본 프롬프트에 들어있는 `{{variable_name}}` 형태의 플레이스홀더는 런타임에 유저가 값을 대입하는 슬롯입니다.
2. **절대 금기 사항**:
   - 변수를 임의의 구체적 값으로 치환하여 하드코딩하지 않는다.
   - 변수 이름을 바꾸거나 삭제하지 않는다.
   - 변수를 둘러싼 괄호 형식을 훼손하지 않는다.
3. **변수 주변 지침 보강**: 변수에 어떤 값이 들어오더라도 프롬프트가 안전하고 견고하게 동작하도록 입력 유효성 검증이나 기본 제약을 추가합니다.

예시:
```markdown
# 나쁜 수정:
"{{topic}}에 대해 글을 써줘" -> "인공지능 트렌드에 대해 글을 써줘" (X - 변수 제거됨)

# 올바른 수정:
"{{topic}}에 대해 글을 써줘" ->
"당신은 테크 전문 저널리스트입니다. {{topic}}을(를) 주제로 하여 다음 조건을 준수하여 분석 리포트를 작성하세요:
1. 대상 독자: 비개발 직군
2. 분량: 1,500자 내외
3. 핵심 요약(Executive Summary) 3줄 포함" (O - 변수 보존 및 구조화)
```

## 3. 대표적인 안티패턴과 해결책

| 안티패턴 (Anti-Pattern) | 문제점 | 해결책 |
| :--- | :--- | :--- |
| **"잘 써줘", "알아서 해줘"** | 모델마다 기준이 달라 결과물 품질 요동 | 대상 독자, 분량, 톤앤매너, 핵심 키워드 명시 |
| **부정문 위주의 지침 ("~하지 마라")** | 금지어에 주의가 쏠려 오히려 실수 유발 | 긍정문 대안 지시 ("A 대신 B 형태로 표현하라") |
| **단일 거대 프롬프트에 모든 작업 몰기** | 중간 추론 과정 누락 및 환각 발생 | Workflow 1 -> 2 -> 3 단계 분해 및 CoT(Chain-of-Thought) 유도 |
| **출력 형식 미지정** | 파싱 불가한 자유 텍스트 출력 | JSON Schema, Markdown 표, 항목별 번호 매김 지정 |
